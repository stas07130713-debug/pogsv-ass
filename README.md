# Подготовка горноспасателей ПОГСВ АСС

Учебно-тренировочное приложение: тесты, генерируемые расчётные задачи и режим тестирования.

## Как запустить

Двойной щелчок по **`Запустить приложение.cmd`** — он сам находит Chrome, Edge,
Firefox или Яндекс.Браузер и открывает в нём приложение.

Можно открыть и `index.html` напрямую, но только если в системе браузером
по умолчанию назначен один из перечисленных. Если `.html` привязан к Internet
Explorer (встречается на рабочих машинах), двойной щелчок либо не даст ничего,
либо откроется браузер, который приложение не поддерживает — в этом случае
пользуйтесь `.cmd`.

Интернет не нужен, установка не требуется. Работает с флешки, из папки на диске,
из локальной сети и с хостинга.

## Проверочные страницы

| Файл | Что показывает |
|---|---|
| `check-normative.html` | Все загруженные нормативные таблицы с цитатами — для построчной сверки с документами. Внизу автопроверка граничных значений. |
| `check-engine.html` | Массовая генерация задач: сколько получило статус VALID, что отклонено и почему, покрытие граничных случаев. Кнопка «Показать примеры» выводит по одной задаче каждого типа. |

| Банк тестовых вопросов | `app/data/questions.js` |
| Устав ВГСЧ, п. 22 | `app/data/normative/ustav-251.js` |

| Реестр типов задач T01–T30 и их статусы | `app/data/tasks/types.js` |

**После любой правки поднимите номер версии в `index.html`** — во всех ссылках вида
`?v=1.0.2`. Без этого браузер и телефон продолжат показывать старые файлы из кеша.
Эта же метка автоматически становится версией приложения в подвале главного
экрана и в отчётах об ошибках — отдельно её нигде прописывать не нужно.

## Телефон

Вёрстка рассчитана на ширину от 320 px и на оба положения экрана. Проверено
на 320, 360, 375 и 740×360 (горизонтально): горизонтальной прокрутки нет
ни на одном экране, поля ввода не мельче 16 px (иначе Safari на iPhone зумит
страницу при касании поля и обратно не возвращает), цели касания — от 44 px.

Учтены также: безопасные зоны iPhone (`viewport-fit=cover` + `env(safe-area-inset-*)`),
изменение высоты окна при появлении адресной строки (`dvh`), задержка 300 мс
перед нажатием (`touch-action: manipulation`) и серая вспышка по касанию.
Правила для сенсорных экранов привязаны к `pointer: coarse`, а не к ширине:
телефон, повёрнутый набок, шире 620 px, но палец от этого толще не становится.

Широкие блоки — схема маршрута и лента тем в «Психологии» — прокручиваются
внутри себя, страница целиком по горизонтали не двигается.

## Как устроена генерация задач

Ни сервер, ни ИИ во время работы приложения не используются. Порядок жёсткий:

```
тип задачи → нормативные правила → значения только из допустимого домена →
проверка совместимости → независимый решатель → эталонный ответ →
обратная подстановка → JSON → текст → схема → сверка текст ↔ JSON ↔ схема → VALID
```

Задача, не прошедшая хотя бы одну из 16 проверок, получает статус `REJECTED`
и пользователю не показывается — генератор берёт следующее зерно.
Ответ пересчитывается валидатором заново из одних только исходных данных,
поэтому расхождение между условием и ответом невозможно.

Схема маршрута строится из того же массива участков, что и текст условия:
отдельных «нарисованных» чисел у неё нет.

## Режимы

| Режим | Что делает |
|---|---|
| Тесты | Вопросы с вариантами ответов, обратная связь сразу, разбор ошибок |
| Задачи | Генерируемые расчётные задачи, пошаговое решение |
| Экзамен | 20 вопросов и 3 задачи под таймером, протокол на печать |
| Психология | Материалы для чтения без проверки знаний |

## Итоги экзамена

Результат живёт в памяти вкладки до её закрытия. Уйти с экрана итогов, не нажав
«Просмотр отчёта», больше не страшно: вкладка «Экзамен» открывает те же итоги —
с разбором ошибок, слабыми темами и печатью протокола. На главном экране
карточка «Экзамен» в этом случае подписана «Результат сохранён».

Новый подход начинается только кнопкой **«Новый экзамен»** и запрашивает
подтверждение — случайное нажатие на вкладку итоги не стирает.
Дата в протоколе — дата завершения экзамена, а не дата печати.

Раздел «Психология» появляется на главном экране автоматически, если в банке
есть вопросы со статусом `STUDY`: там развёрнутые теоретические темы, которые
не сводятся к выбору из четырёх вариантов. Слева меню тем, справа ответ;
на телефоне меню становится горизонтальной лентой над текстом.

## Сообщение об ошибке

Под каждым вопросом и каждой задачей есть кнопка **«Сообщить об ошибке»**.
В окне пишется описание, дальше приложение само собирает письмо: кто сообщил,
номер отделения, должность, дата, раздел, идентификатор вопроса, его текст,
варианты ответа и — для задач — зерно генерации, по которому задача
воспроизводится с теми же числами.

Отправка работает **без сервера и без API**.

**Пока Google Форма не подключена** главная кнопка называется «Отправить письмом»
и открывает почтовую программу с готовым письмом на адрес из `app/config.js`
(`feedback.email`). Рядом всегда есть «Скопировать» — текст обращения ложится
в буфер обмена, и письмо отправляется вручную из любой почты, в том числе
с телефона. Этот путь работает офлайн.

**Форма подключена.** «ПОГСВ сообщение об ошибке», единственное поле
«Описание ошибки» → `entry.2120176204`. Режим `silent`: вкладка не открывается,
пользователь видит зелёное подтверждение прямо в приложении.

Формат обращения подобран под ячейку таблицы. Каждый факт — своя строка вида
`МЕТКА: значение`, важное сверху:

```
ЧТО НЕ ТАК: Неправильная ссылка на документ
ГДЕ: Тесты · Вопрос Q028
КТО: Иванов И. В. · отделение 3 · Помощник командира взвода
КОГДА: 12.08.2026 13:40 · версия 1.6.2
————————————
ТЕКСТ: Через какой промежуток времени…
ВАРИАНТЫ: А. Через каждые 5 минут / Б. Через каждые 3 минуты / …
ВЕРНЫЙ ОТВЕТ: А. Через каждые 5 минут
ОСНОВАНИЕ: Устав ВГСЧ (Приказ № 251), глава 5, п. 38
```

Метки заглавными нужны затем, что Google Таблица показывает ячейку одной
строкой: даже когда переносы схлопываются, по меткам текст разбирается глазом
и режется формулой. Для задач вместо вариантов идут `ЗЕРНО ГЕНЕРАЦИИ` и
`ХОД РЕШЕНИЯ`.

Чтобы данные легли по отдельным столбцам, добавьте в форму вопросы «Фамилия»,
«Отделение», «Должность», «Раздел», «Тип», «Идентификатор», «Текст вопроса»,
«Описание» и впишите их `entry.NNN` в соответствующие ключи `fields`.
Ключ `report` тогда очищается.

**Как подключить другую форму.** Заполните в `app/config.js` блок `feedback.form`:

| Поле | Что вписать |
|---|---|
| `id` | часть ссылки между `/d/e/` и `/viewform` |
| `fields.*` | идентификаторы полей вида `entry.1234567890` |
| `mode` | `'silent'` — отправка молча, `'prefill'` — открыть форму заполненной |

Идентификаторы полей смотрятся так: в форме «⋮ → Получить заполненную ссылку»,
заполнить каждое поле его же названием, «Копировать ссылку» — в ней рядом
с каждым значением стоит нужный `entry.NNN`. Незаполненные ключи просто
не отправляются, лишнего писать не нужно.

Как только `form.id` заполнен, главная кнопка становится «Отправить» и уходит
в форму (нужен интернет), а письмо и буфер обмена остаются запасными путями.
Правки в коде для этого не требуются.

Поле `feedback.formUrl` — старый упрощённый вариант с меткой `{{text}}`
в готовой ссылке. Используется, только если `form.id` пуст.

## Слабые темы

по вопросам только из него, кнопка «Повторить все слабые темы» — сразу по всем.

## Дыхательные аппараты

В `app/data/normative/apparatus.js` внесён **Р-30** — респиратор изолирующий
регенеративный на сжатом кислороде, по РЭ Р30Р.00.000 РЭ1 (ред. 22.03.2022):

| Величина | Значение | Где в РЭ |
|---|---|---|
| Номинальное время защитного действия | 240 мин | прил. 1, расшифровка артикула |
| Давление в кислородном баллоне | 20 МПа | разд. 3 |
| Сигнал снижения давления | 5,5 МПа | разд. 2 |
| Рабочий диапазон температур | от −20 до +60 °C | разд. 2 |

Вместимость баллона из таблицы разд. 3 однозначно не читается, поэтому оставлена
пустой — на расчёты она не влияет.

**Одно допущение, которое нужно знать.** ФНП № 520, прил. 6, п. 2 формулирует
долю рабочего объёма по-разному: для аппаратов на химически связанном кислороде —
«за 75 % номинального времени защитного действия» (прямо по времени), а для
аппаратов на сжатом кислороде — «75 % от объёма газо-дыхательной смеси в баллоне»
(по объёму). Перевод доли объёма в долю времени верен при равномерном расходе.
Тип T11 этим переводом пользуется и **прямо проговаривает это в тексте решения**,
чтобы допущение не выглядело нормой. Для Р-30 получается 75 % от 240 мин = 180 мин.

## Нормативная база

- Приказ МЧС России от 09.06.2017 № 251 (Устав ВГСЧ), ред. от 18.04.2023 № 379
- Приказ Ростехнадзора от 11.12.2020 № 520 (ФНП), с изм. от 08.12.2023 и 20.02.2026

Норм удельного расхода дыхательной смеси (МПа на метр или на минуту) нет ни в одном
из документов проекта — проверено по полному тексту Устава № 251, ФНП № 520 и
Справочника командира отделения ВГСЧ. Поэтому расход всегда задаётся условием задачи
как замеренная величина и помечен как учебный параметр, а не как нормативное требование.

## Персональные данные

Фамилия, номер отделения, должность и результаты хранятся только в памяти вкладки
и никуда не передаются. Закрытие вкладки удаляет их. Протокол печатается
средствами браузера — в окне печати выбирается «Сохранить как PDF».

## Инструмент разработчика

`tools/pdf-extract.ps1` — извлечение текстового слоя из PDF без внешних зависимостей
(нужен для документов, свёрстанных subset-шрифтами). Пример:

```
.\tools\pdf-extract.ps1 -Pdf "..\База знаний\Справочник.pdf" -Out .\текст.txt
```
